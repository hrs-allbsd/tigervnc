vnc-sixel implementation status and measurements
================================================
Updated: 2026-11-15 JST

Completed milestones
--------------------
1. Terminal/RFB viewer, keyboard/mouse input, cursor composition,
   resize, suspend/resume, and restoration on exit/disconnect.
2. Large framebuffer support (64M pixels) and vncviewer-compatible
   credential sources: environment and vncpasswd files.
3. Numeric performance logs and passive shared/view-only real-server
   measurement in a private Xvfb/xterm.  No remote input or screenshots.
4. Indexed fixed-palette encoding and aligned changed-region redraw.
   Identical displayed frames are skipped.  FullFrame is the fallback.
5. X11-independent terminal configure; upstream default builds preserved.
6. Fast terminal queries, XTSMGRAPHICS bounds/colors, manual geometry,
   and an eight-color fallback for limited terminals.
7. Reproducible input-to-image latency measurements, idle-aware frame
   deadlines, and configurable MaxFPS (1..60, default 10).
8. Independent sparse regions with color-run/palette cost estimation;
   SingleRect remains a fallback for diagnosis and comparison.

Controlled local input latency (100 samples)
--------------------------------------------
XTEST injects a key into xterm.  A local RFB fixture changes a response
rectangle, and XGetImage observes the painted pixel.  Input phases use
the same seeded sequence; two warmups are excluded.  This includes local
RFB transport and xterm drawing, but not physical scanout, WAN RTT, or
remote application processing.

Previous timer, 10 fps: median=77.723ms, p95=126.163ms, max=129.607ms
Idle-aware timer, 10 fps: median=46.770ms, p95=82.312ms, max=93.190ms
Idle-aware timer, 30 fps: median=5.799ms, p95=17.677ms, max=25.231ms

Sparse-region workload
-----------------------
The fixture sends the same initial image and 40 paired distant updates.
All 41 RFB updates are decoded in each case; slow terminal output can
coalesce intermediate displayed frames.

Textured, SingleRect: 22 frames, 20242841 SIXEL bytes, 4504873 encoded pixels
Textured, sparse regions: 40 frames, 6104388 SIXEL bytes, 1445056 encoded pixels
Blank, SingleRect: 41 frames, 195166 SIXEL bytes, 8347129 encoded pixels
Blank, sparse selection: 41 frames, 195166 SIXEL bytes, 8347129 encoded pixels

Splitting by area alone increased bytes on blank backgrounds because
SIXEL compresses long single-color runs efficiently.  The final heuristic
accounts for color transitions and per-DCS palette overhead; the blank
fixture therefore retains identical output byte counts.  The estimate is
not a guarantee of optimal compression for every image.

Real-server regression with sparse regions and MaxFPS=30:
  105 frames, 124 regions, 783880 SIXEL bytes in 20.132s.
  CPU=2.224s, encoding=48.326ms total,
  maximum encoding=16.211ms, RSS=147896 KiB.
This is a separate passive observation, not the controlled fixture workload.

Verification
------------
- 29 frontend unit tests: parser, checked dimensions, quantization, damage,
  sparse coverage/fragmentation, and frame scheduling.
- 273 upstream unit tests and the normal vncviewer build.
- Authentication PTY tests: echo, environment, password files, precedence.
- Terminal PTY tests: color limits, missing replies, manual/invalid sizes,
  graphics bounds, fast query completion, and termios restoration.
- Actual xterm pixel comparisons: partial versus forced full redraw,
  black erasure, adjacent colors, lower-right final band; 256/8 colors.
- xterm integration: input, suspend/resume, resize, signal/disconnect
  termination, and termios/private-mode restoration; 6K framebuffer.
- Paused xterm reader: bounded pending output, RFB update progress, and
  preservation of the latest framebuffer on resume.
- Terminal build explicitly disables X11 discovery and links no Xlib/FLTK.
- Port builds at nice 20 and passes check-plist and stage-qa.

Remaining work, in order

   cursor/CopyRect/server-resize coverage.
2. Optional photographic palette and further tuning of the sparse-region
   compression estimate, guided by representative workloads.
3. Paste-rate limiting, configurable Escape timeout, and local help.
4. TLS/RSA-AES interoperability and a host-key trust store/user workflow.
5. Publish reviewed source commits, then replace port backports with a
   newer pinned GitHub source commit; clean poudriere jail validation.
6. pjm native Git/CMake support and safe import of the existing clone.
   The pjm checkout has unrelated uncommitted work and was not modified.
   Use the separate pjm-design.txt proposal before implementing this item.

Clipboard, tmux/screen, other terminal families, audio and H.264 remain
outside the initial version.  Terminal protocols cannot report ordinary
physical key releases reliably; a renderer change cannot remove that limit.

Reproduce
---------
See README.txt for build, authentication, terminal and test commands.
Performance flags: -PerfLog FILE, -ViewOnly, -FullFrame, -SingleRect, -MaxFPS.
Harness: tests/real-server-perf.py (explicit private credential-file path).
Full summary files and logs live outside the Git source tree in records/.
Never add CREDENTIALS.txt, live-server screenshots, or credentials to Git.

Local pointer milestone (2026-11-15)
-----------------------------------
Referenced Xsixel's hw/kdrive/sixel/hostcursor.c and client-xterm.c.
Added an optional dynamically loaded XFixes backend.  Native pointer
hiding follows image bounds and focus, and is balanced on suspend/exit.
The server releases the hide request even when the viewer is killed.
Unlike a pointerMode escape, this does not replace the user's xterm
resource setting.  HideLocalCursor=0 disables the backend.

Actual xterm/Xvfb cursor-pixel comparisons pass for normal termination,
disconnect, SIGKILL, both scrollbar positions, disabled hiding, ViewOnly,
missing WINDOWID, and servers without a cursor shape.  The remote cursor
is also checked in the rendered image.  ViewOnly intentionally leaves
the native pointer visible.  X11 access and WINDOWID are required;
remote SSH sessions without them retain the terminal pointer.

Validation after the local pointer change:
- Backend enabled and disabled: 29 frontend tests each.
- Authentication, terminal negotiation, and 6K xterm integration pass.
- 100 local input-to-image samples at MaxFPS=30: median=6.225ms,
  p95=16.872ms, maximum=32.207ms.  This is a regression observation,
  not a controlled comparison against the earlier timing run.
- Real server, shared ViewOnly, 20.067s: 136 updates, 64 frames,
  494115 SIXEL bytes, CPU=1.733s, RSS=149300 KiB.
  No remote input or live-server image was captured.  Native pointer
  behavior was checked against the private local cursor fixture.
- Port revision 5 builds at nice 20, passes check-plist and stage-qa;
  staged binary passes native pointer, authentication and terminal tests.
  HOSTCURSOR defaults on and declares X11/Xfixes runtime dependencies.
  The GitHub snapshot remains fixed; patches contain unpublished changes.
